# 演示与面试讲解提纲

## 演示前准备

1. 启动 MySQL；可选启动 Redis、RabbitMQ 和 MinIO。
2. 在项目根目录执行 `. .\scripts\Set-JwtSecret.ps1`，再启动后端。
3. 在 `frontend` 目录安装依赖并执行 `npm run dev`。
4. 访问 `http://localhost:5173`，确认欢迎页显示“后端服务：连接正常”。

默认配置不依赖 RabbitMQ、MinIO 或真实 AI：提交幂等会回退至数据库唯一约束，通知同步写库，附件保存到本地目录，识别使用 Mock 客户端。因此演示主流程不会被可选基础设施阻塞。

## 建议演示路径

1. 以员工身份登录，创建一张包含至少一条费用明细的草稿。
2. 上传一份 PDF 或图片票据，打开下载确认文件可读取；重复上传同一文件，说明 SHA-256 去重保护。
3. 对附件执行“发票识别”，展示待确认的号码、日期、金额、商户和置信度；手工修改一项后确认，展示金额已回写明细。强调 AI 不会直接改正式数据。
4. 保存草稿并提交审批；连续发送相同 `Idempotency-Key` 的请求，说明只会创建一次审批任务。
5. 切换经理身份，通过或驳回。通过后展示财务待办与申请人的站内通知。
6. 切换财务身份，通过财务审核并确认付款；回到员工视图展示完成状态、审批历史和付款通知。
7. 以管理员或审计员查看操作日志，说明 `X-Request-Id` 可关联请求，失败操作会留下不含敏感数据的 `FAILURE` 审计记录。

## 可演示的失败与权限场景

- 未登录访问业务接口：401；角色不匹配：403。
- 非申请人访问、上传或下载他人附件：拒绝。
- 非草稿/驳回状态编辑报销单、附件或确认识别建议：拒绝。
- 缺少驳回意见、提交空明细、重复处理已完成审批任务：返回参数或状态冲突错误。
- 模拟乐观锁冲突：业务事务回滚，但失败审计日志保留。

## 面试讲解顺序

### 1. 先讲业务闭环

员工填报、上传票据、人工确认识别建议、提交；经理审批；财务复核与付款；系统通知申请人并保留审批和审计历史。

### 2. 再讲一致性和权限

金额由后端以 `BigDecimal` 汇总；状态机限定合法转换；`version` 乐观锁处理并发；报销单、附件和发票建议都执行归属与状态校验。审批记录只新增，不覆盖历史。

### 3. 讲可靠性设计

提交使用 Redis 抢占和数据库唯一记录双层幂等；消息通知可走 RabbitMQ，消费者按 `messageKey` 去重，服务不可用时退化为同步写库；失败审计通过 `REQUIRES_NEW` 独立事务保存。

### 4. 讲外部服务解耦

附件通过 `AttachmentStorage` 抽象，在本地文件与 MinIO 间切换；发票识别通过 `InvoiceRecognitionClient` 抽象，在 Mock 与真实 AI 适配器间切换。外部服务异常不阻断手工报销。

### 5. 诚实说明当前边界

项目定位为可运行、可测试、可演示的单体学习项目。RabbitMQ 的 Confirm/Outbox、死信治理，MinIO 分布式部署和生产级 AI 评测属于下一阶段，而非当前 MVP 的承诺。
