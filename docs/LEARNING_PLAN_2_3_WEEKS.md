# 2-3 周学习与执行计划

本计划针对当前项目 `expense-platform` 的实际骨架制定。目标不是一次完成所有生产级能力，而是在 15 个工作日内做出一条可演示、可测试、可解释的核心链路：

> 用户登录 -> 创建报销单 -> 添加明细 -> 提交 -> 经理审批 -> 财务审核/付款 -> 查询通知与审计记录

建议每天投入 2-4 小时，其中 30%-40% 用于阅读原理和现有代码，60%-70% 用于编码、测试和复盘。

## 交付边界

### 必须完成（MVP）

- 用户、部门、角色的查询与基础管理
- BCrypt 密码校验、JWT 登录、角色授权，明确区分 401/403
- 报销单和明细的增删改查，后端用 `BigDecimal` 计算总额
- 报销单提交、撤回、审批通过/驳回、财务付款
- 审批记录不可修改，非法状态转换被拒绝
- 前端至少完成登录、我的报销单、报销单编辑、待审批列表和详情页
- Controller、Service、Mapper 的单元/集成测试及 Swagger 验收脚本

### 时间充足再做（增强项）

- Redis 提交幂等和简单登录限流
- RabbitMQ 审批事件与站内通知
- MinIO 文件上传、SHA-256 去重
- AI 发票识别的结构化 JSON、超时重试和人工确认

## 任务清单与执行清单

### 第 1 周：基础设施、用户和认证

| 天 | 学习任务 | 执行任务 | 当天验收物 |
|---|---|---|---|
| 1 | 阅读 `README.md`、`pom.xml`、Vite 配置、`V1__init_schema.sql`；理解请求从 Vue 到 Spring Boot 的路径 | 启动 MySQL/后端/前端；调用 `/api/health`；用 Swagger 记录现有接口 | 环境检查记录；能解释每个服务用途 |
| 2 | Spring MVC 分层、依赖注入、MyBatis-Plus CRUD、Flyway 迁移 | 建立 `user`、`department`、`role` 模块的 entity/mapper/service/controller；先完成分页查询 | Swagger 可分页查询用户和部门 |
| 3 | DTO/VO 边界、Bean Validation、统一响应和异常处理 | 添加创建/修改用户 DTO；实现用户名、工号重复校验；补全统一错误码 | 参数错误返回 400；重复用户名返回明确业务错误 |
| 4 | BCrypt、认证(Authentication)与授权(Authorization)、SecurityFilterChain | 实现登录接口、密码校验、JWT 签发/解析；去掉业务接口的临时 `permitAll` | 登录成功拿到 token；无 token 为 401 |
| 5 | RBAC、SecurityContext、前端路由守卫和 Axios 拦截器 | 按 EMPLOYEE/MANAGER/FINANCE/ADMIN 保护接口；完成 Vue 登录页和基础布局 | 越权访问为 403；刷新页面仍能恢复登录态 |

### 第 2 周：报销单和审批状态机

| 天 | 学习任务 | 执行任务 | 当天验收物 |
|---|---|---|---|
| 6 | 一对多表、事务边界、逻辑删除、金额精度 | 完成报销单/明细 entity、mapper、DTO、VO；实现草稿创建和明细维护 | 能保存草稿；总额等于有效明细之和 |

| 天 | 学习任务 | 执行任务 | 当天验收物 |

## 每日执行模板

1. 先写今天要回答的 3 个原理问题，例如“为什么总额不能信任前端？”
2. 阅读对应现有代码和表结构，画出一张简图。
3. 只实现一个可验证的小切片：接口、数据库变更、前端调用、测试一起完成。
4. 用 Swagger 或测试复现成功、失败、越权、重复请求至少各一次。
5. 在学习日志中记录：完成内容、遇到的错误、下一步、一个可复述的原理。

## 取舍与风险

- 如果环境或外部 AI 服务不稳定，优先保证手工录入和审批闭环，AI 只做可插拔增强。
- Redis、RabbitMQ、MinIO 不应阻塞第 1-2 周；先用数据库和同步调用完成正确性，再接入基础设施。
- 不建议在 3 周内追求复杂工作流引擎、微服务拆分或完整财务对账，这些会扩大范围而降低可验收性。

## 最终验收场景

用四个角色准备数据：员工、部门经理、财务、管理员。员工创建两条明细并提交；经理批准；财务付款。再验证：员工不能审批他人单据、重复提交不产生重复任务、并发审批只有一次成功、驳回后可修改并重新提交、AI/消息服务不可用时手工流程仍可完成。
