# 需要亲自完成的核心任务

环境和表结构已准备好。下面的任务按照依赖关系排列，每次只学习完成当前任务所需的知识。

## 1. 用户模块

亲自实现：

- `SysUser`、`Department`、`SysRole` 实体与 Mapper
- 用户和部门的分页查询
- DTO、VO 转换
- 统一响应、业务异常和参数校验

需要理解：Controller、Service、Mapper 分层；依赖注入；MyBatis-Plus CRUD；分页；DTO 与 VO 的边界。

验收：Swagger 能创建用户、查询用户，用户名重复时返回明确业务错误。

## 2. 登录与权限

亲自实现：

- BCrypt 密码验证
- JWT 签发和解析
- Spring Security 认证过滤器
- 员工、主管、财务、管理员接口权限

需要理解：认证与授权；SecurityFilterChain；过滤器；SecurityContext；JWT 的优缺点。

验收：删除 `SecurityConfig` 中的临时 `permitAll`，未登录访问业务接口返回 401，越权返回 403。

## 3. 报销单与明细

亲自实现：

- 草稿创建和编辑
- 费用明细增删改
- 后端使用 `BigDecimal` 汇总总金额
- 本人报销单分页与详情
- 报销单数据权限

需要理解：一对多表设计；事务；逻辑删除；分页；金额计算；为什么不能信任前端总金额。

验收：只能编辑自己的草稿，总金额始终等于有效明细之和。

## 4. 审批状态机

亲自实现：

- 提交、主管通过、主管驳回
- 财务通过、驳回和付款
- 员工撤回、驳回后重新提交
- 审批任务与不可变审批记录
- `version` 乐观锁并发控制

需要理解：状态机；`@Transactional`；事务失效；MVCC；乐观锁；非法状态转换。

验收：两次并发审批只能有一次成功，任一步骤失败时数据整体回滚。

## 5. Redis 幂等

亲自实现：

- 获取一次性提交令牌
- Redis `SET NX` 防重复提交
- 数据库 `idempotency_record` 最终保障
- 简单登录限流

需要理解：幂等；缓存过期；缓存一致性；穿透、击穿和雪崩。

验收：连续提交十次只产生一套审批任务。

## 6. RabbitMQ 通知

亲自实现：

- 事务提交后发布审批事件
- 消费事件并创建站内通知
- 使用 `message_key` 防重复消费
- 失败重试和错误日志

需要理解：交换机、队列、路由键；确认；重试；消息丢失和重复。

验收：重复投递同一消息只产生一条用户通知。

## 7. AI 票据识别

亲自实现：

- 上传票据
- 调用多模态模型并要求结构化 JSON
- 校验模型返回的日期和金额
- 用户确认后才写入正式字段

需要理解：结构化输出；超时与重试；Prompt 约束；幻觉；密钥管理。

验收：AI 不可用时核心报销流程仍然可以手工完成。

## 推荐包结构

```text
com.shixi.expense
├── auth
├── user
├── report
├── approval
├── notification
├── invoice
├── common
└── config
```

按业务模块组织，每个模块内部再放 controller、service、mapper、entity、dto 和 vo。不要把所有 Controller 或实体堆在全局同名目录中。
