# 事务与故障恢复

## 通知 Outbox

启用 RabbitMQ 时，报销 / 审批事务写入 `notification_outbox`，与业务一起提交或回滚。发布线程不承担业务提交后的唯一发送机会。后台任务领取到期记录并写入 token / 60 秒租约；发布使用持久化消息、correlated confirm 和 mandatory return，确认 ACK 且没有被退回才标记 DONE。失败保留 PENDING，并使用最长 300 秒的退避重试。

进程在发送后、更新 DONE 前退出可能产生重复投递；消费者以 `(message_key, recipient_id)` 唯一键去重，这是至少一次投递设计。只有确实存在相同通知时，唯一键冲突才被当作重复成功。消费者失败重试三次后进入 `.dead` 队列，需要人工排查和重放；publisher confirm 不代表消费者已完成。

默认关闭 RabbitMQ 时，通知直接加入当前数据库事务。启用异步模式必须保持 BACKGROUND_JOBS_ENABLED=true，关闭后台任务会暂停 Outbox 发送和附件清理。

## 附件补偿

文件操作无法加入 MySQL 事务。上传前先用独立事务持久化 15 分钟后可清理的任务，再由上传事务锁住该任务行、写文件、保存元数据、标记任务 DONE。事务回滚时回调立即删除文件；删除失败，或进程崩溃来不及回调，数据库任务仍存在。后台重试删除前检查已提交附件引用，避免删除合法上传。

删除附件时，元数据删除与清理任务在同一数据库事务中提交；先完成数据库提交，再异步删除文件。数据库回滚不会误删仍被引用的文件。存储故障时，元数据保持删除，文件清理继续重试。

后台领取与完成使用条件更新和 token，过期任务允许接管，旧 worker 不得完成新 worker 的任务。文件删除操作应保持幂等；永久性存储错误不会自动变成成功。

## 运维边界

当前默认每 3 秒每类领取一条任务，适合演示、小规模验证，未做吞吐量承诺。DONE 任务和幂等快照没有自动归档；生产需要保留期、积压 / attempts 告警、死信重放及存储超时策略。异常记录只保存固定的安全提示，日志不写 Token 或外部服务凭据。

Flyway V8 增量增加 token/version 与两张任务表，不改旧迁移。旧 PROCESSING 记录等待租约过期后可接管；旧成功记录继续重放。
